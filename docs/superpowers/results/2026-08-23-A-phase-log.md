# Phase A decision record: controller rulings (2026-08-23)

Plan: `docs/superpowers/plans/2026-08-23-phase-a-instrumentation.md`
Spec: `docs/superpowers/specs/2026-08-23-backlog-completion-design.md` §2

Phase A's execution ledger (`.superpowers/sdd/2026-08-23-phase-a-instrumentation/progress.md`)
is gitignored and does not survive merge. It records fifteen controller rulings made while
running the phase — decisions about the plan, the gate, and how to read the data, made
before or alongside the implementation work rather than after it. This document is their
provenance: what was decided and what it costs if the decision turns out to be wrong. Two
findings from that ledger that did not otherwise land in a committed document — F1 (the
`hoClamp` observation) and F4 (no client `@@FINAL` line in this phase) — are addressed
separately, in `docs/EVALUATION.md` items 7 and 14 respectively.

| Ruling | Decision | Cost if wrong |
|---|---|---|
| P1 | The Task 0 baseline capture and the Task 6 gate must filter `@@FINAL` lines identically (`role=server` on both sides), or a `Compare-Object` diff could be an artefact of the filter, not of the code. | None identified — a narrower filter cannot hide a real server-side change. |
| P2 | Task 7's epoch-alignment comparison sweeps `-Sweep ticks -Values "1800"`, not `-Sweep seconds` paired with `-Ticks 1800` — the latter reads as a realtime sweep while actually running paced. | The comparison would run at an unintended tick count, visible in the manifest. |
| P3 | Every `analyse.py` invocation targets an experiment directory (via `run-experiments.ps1`), never a bare `measure.ps1` run dir — `analyse_experiment` requires `experiment.json` and returns a false "no runs found" otherwise. | None — the baseline becomes one run inside an experiment wrapper; no measurement changes. |
| P4 | Briefs carry `msbuild`'s full path explicitly, since it is not on `PATH`. | None — the path is verified by running it. |
| P5 | Accept the CMake-regenerated `.sln`/`.vcxproj.filters` dirty-tree flag on every run manifest for this phase; do not commit or gitignore those files (out of scope) or revert them post-configure (risks GUID mismatch). | Run manifests overstate irreproducibility with a dirty flag that cannot mask a real difference, since baseline and gate runs are dirty identically. |
| P6 | The Task 0 baseline stands despite `ownership_gap_ticks=84`: the gap is the documented `--handoff-lookahead 0` behaviour (Phase D's target), not an unexplained failure, and both baseline and gate runs share it identically. | None — a baseline of current behaviour should encode a known, present defect as normal. |
| P8 | Every `build-deploy.ps1` invocation in the plan passes `-Config Release` explicitly (the script defaults to Debug). | None — Release is what the constraints already required; the Task 0 implementer had already caught the omission once. |
| P9 | Task 6's gate is re-derived rather than attempted as originally specified ("exact `@@FINAL` equality"): a validity precondition (clean per `analyse.py`), exact equality on a stable field set, range comparison on the rest across 3 repeats, plus a structural argument. | The gate is weaker than "identical" — a change that perturbs only the varying fields within their natural spread would pass. No stronger instrument is available on this machine. |
| P10 | Task 9's client-count comparison halves `--objects` for the two-client run (`--objects` is per client, verified in code and empirically), holding total world size constant across the comparison. | If `CreatePlayerObjects` were not in fact per-player at this scale, the two-client run would use half the intended world — but the added `objPreseed` cross-check would catch that before it was reported. |
| P11 | `haloLate` is reclassified out of the gate's stable (pinned-at-zero) set into a range check, on evidence from a counterfactual run of the unmodified pre-change commit that produced 526/66 under current machine load with zero code change. | The gate loses the ability to detect a Phase A change whose only effect is to perturb halo lateness — a named, narrow blind spot, not a hole, since no mechanism connects Phase A's diff to halo timing. |
| P12 | `CLAUDE.md`'s reproducibility claim (exact end state and conservation under `--run-ticks --fixed-step`, ±1 handoff counts) is corrected in Task 8, the stale-documentation task, rather than deferred to a later pass. | `CLAUDE.md` — loaded into every session — would keep asserting a claim this phase's own data disproved. |
| P13 | The Task 7 epoch-alignment question is re-framed and salvaged from the six runs already taken (comparing halo counters, which do have a code path at the default `--halo-lookahead 4`) rather than re-run at non-zero `--handoff-lookahead`. | The epoch-alignment question for handoff scheduling specifically stays open one phase longer; the standing decision (leave `--epoch-align-us` at 0) is unaffected because every published run uses `--handoff-lookahead 0`, where the flag provably cannot matter. |
| P14 | Task 9's E8 rewrite fixes its four Critical review findings by re-interpreting data already on disk; it does not re-run experiments and does not investigate, inside this phase, which commit changed the snapshot path between the published build and this one. | Phase A closes with a documented open regression (item 13) rather than a resolved one — the honest state, versus misfiling a real change as realtime variability, which the halo column's near-identical packet rate refutes. |
| P15 | The published-build counterfactual for E8 is stated as marginal and too close to call at radii 25/50 (within 1%/6% of the failure threshold, against ~10% repeat noise, itself optimistically biased) and failing at radius 100 — not as a claim that survives on its own merits. | The write-up is more conservative about the published build than strictly required — the safe side to err on, given the counterfactual's own stated optimistic bias. |
| P16 | Task 9's round-4 patch (two Important findings, confined to one paragraph and one sentence, corrected text already present elsewhere in the same document) is applied and controller-spot-checked rather than sent through a fifth review round. | A fourth swing could land uncaught by an independent reviewer — mitigated by writing the exact corrected text into the fix brief so no judgement call was required, and by checking the arithmetic before signing off. |
